The problem

Sprint planning runs on four guesses.

How big is it?a planning-poker vote
Who takes it?whoever looks free
What will it cost?last quarter's spreadsheet
What could go wrong?found out on day nine

SprintIQ replaces each guess with an estimate that says how sure it is. See the research gap

One board. Four models underneath.

SprintIQ is a complete multi-tenant Agile tool: backlog, boards, sprints and reports. Each AI model attaches to the decision it informs, and every suggestion waits for a person to accept it.

  • Accept, override or dismiss every suggestion
  • Every prediction stored with its inputs
  • Tenant data isolated, and tested

Method notes for M1

Story points: XGBoost over 150 TF-IDF terms and 34 structural features, with LightGBM P20/P80 quantiles calibrated by conformalised quantile regression (δ = 0.594) and snapped to the Fibonacci scale. Velocity: XGBoost trained without the domain feature, with few-shot weighted retraining. Trained on synthetic datasets (3,000 stories; 3,000 sprints across five domains) and scored on held-out data.

Method notes for M3

A stacking ensemble predicts developer performance; the ranking blends it with skill match, workload balance and growth. Weights come from the Analytic Hierarchy Process (consistency ratio below 0.10), refined by simulation-based SLSQP optimisation. Results are from simulations with synthetic developer and task profiles.

Method notes for M4

At planning, the sum of task estimates × blended rate beat the ML candidate (MAPE 23.45% vs 25.65%), so the formula ships. Mid-sprint, gradient boosting predicts the remaining effort and adds the actual cost incurred. Drivers are exact Shapley values over nine factors (all 512 coalitions). Training data is synthetic.

Method notes for M2

CatBoost with two heads per risk: how bad (Low, Medium, High) and how likely. One model each for over-budget and requirement change; a fine-tuned DistilBERT model covers communication and collaboration risk. Board events adjust the scores live, and an LLM advisor explains each risk and recommends steps. Training data is synthetic.

How it's built

Four layers, one inference path.

Every prediction returns the same envelope (value, range, drivers, explanation) and is stored with the exact inputs that produced it.

  • Next.js 16 · React 19

    Story estimate panel, velocity panel, risk board, cost widget and the Copilot.

  • Spring Boot 3.3 · Java 21

    A modular monolith with one inference path: flag → cache → call → record. Multi-tenant, with isolation proven by tests.

  • FastAPI model service

    The M1–M4 bundles behind /predict/* endpoints, with the contract checked at start-up.

  • PostgreSQL 16 · Redis 7

    Prediction ledger, feedback, model registry and tenancy.

The research

From gap to method.

The gap

Tools record. They don't predict.

Agile tools record and report work. They don't predict it, explain it, or say how sure they are.

Research gap
Our method

Design Science Research

Build an artefact, evaluate it against honest baselines, iterate. One loop for the platform and one for each model.

Methodology
What's new

Ranges and reasons, in one tool

Four models, each with a calibrated range and its drivers, inside the tool teams plan in, plus a Copilot that asks before it acts.
